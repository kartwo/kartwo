## 已迁移配置页的验收边界

收款按 Stripe/PayPal 分别保存；密钥只提交、不回填，保存后清空输入。环境变量配置只读，店主仍可测试已保存配置；员工不可进入收款与邮件，域名保留独立权限，演示不可保存或测试。域名保存保留重启及本地不签发证书提示；SMTP 保留密码空白字符和留空不变语义。向导复用相同页面；读取失败不展示可编辑空配置，401 清除会话，正在加载或提交时不能跳到下一步。

店铺品牌保留授权员工可编辑和演示只读，名称与 Logo 共用操作锁，上传失败保留旧图，上传或删除 Logo 不覆盖未保存的名称。博客及客服设置店主可写、员工只读；开关与留存数值严格解析，读取失败不展示默认可保存表单，保存失败保留输入供重试。完整留言留存 1–24 个月、IP 留存 7–90 天保持原有规则。

账号设置保留店主修改用户名/可选主密码及员工只改自身密码；确认成功后立即清空会话，错误密码保留当前会话。翻译密钥不回填、空值保留，页面加载和保存均不自动调用翻译。备份保留本地策略重启生效、WebDAV 保存后测试及冷启动所需环境配置提示；环境只读字段从写入中省略，密码空值省略且空白原样保留，配置保存失败不发起远端测试，测试失败仍清空已经保存的密码。全环境配置允许店主仅测试、无需提交只读值。

配送保留按洲分组、中文/英文/代码搜索、范围全选/清空、默认及特殊运费、规则新增/编辑/确认删除；金额使用十进制字符串和 BigInt 精确转分，拒绝舍入/指数/溢出。只读账号可搜索和查看规则，编辑动作依据 settings.shipping。特殊规则只能选已保存启用国家；删除正在编辑的规则后重置编辑器。政策资料保留七洲时效，最大天数须不小于最小天数；资料编辑依据 settings.policy，生成页面额外需要 content.manage。生成前保存当前资料，覆盖正文前确认；取消不写入，保存失败不生成，生成失败明确已保存资料。现有草稿/发布保留语义继续由后端生成器负责。

用户与角色页面仅店主可访问；预设角色名称固定但权限可编辑，自定义角色可创建、改名、改权和删除，店主超管单独展示且无员工操作入口。角色依赖按现有服务端规则校验，用户/角色/会话/退款等店主专属权限不出现在可分配清单。邀请、停用/恢复、角色调整、密码重置和退出设备沿用原接口；重置、退出设备和删角色均先确认，仍有员工的角色须先调整。邀请链接严格限定本站固定入口与令牌格式，仅保留当前页面内存，支持复制/隐藏，跳页或会话过期清除。写入成功而列表刷新失败保留刚生成的邀请及成功结果，明确提示刷新核对，不误报写入失败或自动重发。

## 验证方式

- `npm test`：3 项共用 Node 工具测试 + 271 项 React DOM、路由、会话、接口契约及业务交互测试。
- `npm run typecheck`：严格 TypeScript 检查。
- `npm run build`：全部测试、严格 TypeScript、唯一正式 React 入口构建；不再存在迁移专用构建。
- `npm audit --registry=https://registry.npmjs.org --audit-level=high`：包含开发依赖的安全门禁。

React DOM 测试文件以单 worker 顺序执行，避免每个 jsdom/Ant Design 实例同时加载造成资源争抢；用例内部的请求并发与竞态断言仍保留，未放宽超时或删减场景。

3. 依次查看“可发货”“资金待核对”“退款待处理”“已发货”；退款后已有的发货记录应继续出现在“已发货”。同一订单可属于多个待处理视图，不能把各视图数量相加当作总订单数。
4. 如果现有订单超过 20 条，切换下一页和每页条数，核对订单不重不漏。少于 20 条时无需为了验收重新填数据，大结果集由隔离自动测试覆盖。
5. 用没有客户资料权限的现有测试员工登录，确认只提示订单号搜索；用已知测试邮箱搜索应没有结果，不能显示邮箱或导出 CSV。具备资料权限的员工可搜索邮箱，仍不能退款或导出。
6. 缩窄浏览器窗口，确认“菜单”抽屉点击当前订单页后也收起，表格在自身内部横向滚动，页面不整体横移。付款/退款/发货操作继续按沙箱专项验收，本片搜索检查不需要执行这些操作。

## 博客正式入口切换后的人工验收

1. 复用已有常驻验收库进入新版后台，不清空商品或配置，无需重填数据。
2. 在“博客文章”新建草稿，输入英文标题确认链接跟随标题；手改链接后继续改标题，确认不覆盖。加粗、设置标题和颜色、插入表格，分别上传封面和正文图片。
3. 保存后从列表重新打开，确认图文、封面、链接和草稿状态保留；发布后打开店面文章核对图片和排版。保存后的链接应固定。
4. 打开一篇旧 Markdown 文章，检查转换提示和原图文；保存后重新打开确认内容。视频使用 YouTube/Vimeo 链接，错误链接应提示且不插入。
5. 用只有 blog.view 的员工查看，确认可以阅读、不能上传保存删除；公开演示不显示真实草稿。完整权限回归在统一切换时执行。

## 商品正式入口切换后的人工验收

1. 复用常驻验收库进入新版后台“商品”，无需清空已有商品和图片。
2. 新建草稿，填写英文标题，确认自动生成链接；设置一个轴和几个取值，生成组合。价格留空应阻止保存，填 0 或两位小数可保存，库存须为整数。
3. 填好价格后更改轴，确认提示重新生成；取消重新生成时原输入应保留。保存后进入编辑页，链接固定，上传图片并填写英文 alt。
4. 修改当前行价格与库存并保存，重新打开核对；只改价格时，不应重设其他库存。用只有改价或库存权限的测试员工，确认只能维护对应字段，不能因此编辑基本信息或上传图片。
5. 草稿改为上架并保存，回店面核对；精选只对上架商品开放。删除商品和图片前均应确认，取消不删除。
6. 演示中已有示例商品只读，自有商品只能是草稿，达到临时商品/图片额度后禁用继续创建或上传。翻译由店主手动点击；未配置服务只提示，不自动发送文字。

## 订单正式入口切换后的人工验收

1. 复用常驻验收库，只使用支付沙箱订单验收退款与发货，不重建商品或配置。
2. 在列表打开订单，核对金额、运费、付款和发货状态；店主导出 CSV，分别选择状态和起止日期，确认包含结束当天，错误日期范围不能导出。
3. 用授权员工验证收货信息与发货；缺少客户资料权限时邮箱、地址和支付参考号应隐藏，也不能发货。演示只读脱敏；员工没有退款、平台核对或撤销访问入口。
4. 在一笔有可退余额的沙箱订单上选择付款，填写小额退款，核对确认框中的交易号、币种和金额。取消不提交，确认后在持久退款请求中查看状态。退款后原发货记录应保留。
5. 待核对请求优先“继续原退款请求”或填写平台退款编号核对，不新建重复退款。详情刷新失败时应暂停新退款和发货，刷新确认最新记录后才恢复；未知原请求仍需继续核对。
6. 在沙箱订单确认“撤销顾客访问”，原设备查看凭证应失效，顾客仍可用订单邮箱重新验证；订单与付款状态不变。真实 SMTP/支付回调、跨设备与生产部署另按 A 阶段验收，当前接口桩测试不能替代。
