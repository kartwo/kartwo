## Stripe 连接测试正确性（2026-10-26）

核对官方[账户对象](https://docs.stripe.com/api/accounts/object)和[密钥格式](https://docs.stripe.com/keys)发现，账户对象没有可用于模式判断的 `livemode` 字段；账户级 `sk_test_` / `rk_test_` 与 `sk_live_` / `rk_live_` 前缀区分环境。原代码将缺失字段当作 `false`，正常正式账户会被误判，不完整的测试响应又可能被接受。隔离回归已实际复现这两类问题及配置变化后误报成功。

修复保留原 `GET /v1/account` 和已钉 API 版本，不改变现有密钥权限、支付创建、回调或退款流程。密钥和配置模式在同一锁内取快照；未知格式、空凭证和模式不符在发请求前拒绝。通过真实认证后，必须收到 HTTP 200、合法账户对象和账户编号；读取报错、超限、缺失或错误对象不能报成功。返回前核对原配置仍有效，密钥被替换、锁定或切模式后须重新测试。内部连接错误也不再携带网关原文或凭证，后台原有固定安全提示保持。

新增五个 Go 测试函数，覆盖两种环境的普通/受限密钥、默认测试模式、环境覆盖、错误模式/格式、非法响应、完整 JSON 后读取失败、取消、配置变化，以及实际后台鉴权/CSRF/演示拒绝、成功审计与配置不变。先用原实现得到明确失败，修复后三轮竞态通过：payment 2.580s、admin 10.374s；完整支付包竞态通过（59.510s）。全仓 vet/lint 为零问题，Linux/AMD64 默认 govulncheck 完成，可达及导入包漏洞为零，既有一个未导入模块告警保留。应用依赖、迁移、前端源码及正式资源不变；后续提交仍按 PR 当前 HEAD 的远端门禁验收。

本机程序已在完整在线快照和归档校验后更新为 `dev-stripe-connection-review-20261026`，新增迁移零；换版后、连接操作前，49 表原记录、媒体配置、数据目录外钥匙和 90 个嵌入资源字节/MIME 保持，匿名受保护接口仍拒绝且私密响应头完整。自动备份按原保留策略轮换一份，完整手工恢复包保留旧包。

## 博客正式入口切换后的人工验收

1. 复用已有常驻验收库进入新版后台，不清空商品或配置，无需重填数据。
2. 在“博客文章”新建草稿，输入英文标题确认链接跟随标题；手改链接后继续改标题，确认不覆盖。加粗、设置标题和颜色、插入表格，分别上传封面和正文图片。
3. 保存后从列表重新打开，确认图文、封面、链接和草稿状态保留；发布后打开店面文章核对图片和排版。保存后的链接应固定。
4. 打开一篇旧 Markdown 文章，检查转换提示和原图文；保存后重新打开确认内容。视频使用 YouTube/Vimeo 链接，错误链接应提示且不插入。
5. 用只有 blog.view 的员工查看，确认可以阅读、不能上传保存删除；公开演示不显示真实草稿。完整权限回归在统一切换时执行。

## 商品正式入口切换后的人工验收

1. 复用常驻验收库进入新版后台“商品”，无需清空已有商品和图片。
2. 新建草稿，填写英文标题，确认自动生成链接；设置一个轴和几个取值，生成组合。价格留空应阻止保存，填 0 或两位小数可保存，库存须为整数。
3. 填好价格后更改轴，确认提示重新生成；取消重新生成时原输入应保留。保存后进入编辑页，链接固定，上传图片并填写英文 alt。
4. 修改当前行价格与库存并保存，重新打开核对；只改价格时，不应重设其他库存。用只有改价或库存权限的测试员工，确认只能维护对应字段，不能因此编辑基本信息或上传图片。
5. 草稿改为上架并保存，回店面核对；精选只对上架商品开放。删除商品和图片前均应确认，取消不删除。
6. 演示中已有示例商品只读，自有商品只能是草稿，达到临时商品/图片额度后禁用继续创建或上传。翻译由店主手动点击；未配置服务只提示，不自动发送文字。

## 订单正式入口切换后的人工验收

1. 复用常驻验收库，只使用支付沙箱订单验收退款与发货，不重建商品或配置。
2. 在列表打开订单，核对金额、运费、付款和发货状态；店主导出 CSV，分别选择状态和起止日期，确认包含结束当天，错误日期范围不能导出。
3. 用授权员工验证收货信息与发货；缺少客户资料权限时邮箱、地址和支付参考号应隐藏，也不能发货。演示只读脱敏；员工没有退款、平台核对或撤销访问入口。
4. 在一笔有可退余额的沙箱订单上选择付款，填写小额退款，核对确认框中的交易号、币种和金额。取消不提交，确认后在持久退款请求中查看状态。退款后原发货记录应保留。
5. 待核对请求优先“继续原退款请求”或填写平台退款编号核对，不新建重复退款。详情刷新失败时应暂停新退款和发货，刷新确认最新记录后才恢复；未知原请求仍需继续核对。
6. 在沙箱订单确认“撤销顾客访问”，原设备查看凭证应失效，顾客仍可用订单邮箱重新验证；订单与付款状态不变。真实 SMTP/支付回调、跨设备与生产部署另按 A 阶段验收，当前接口桩测试不能替代。
